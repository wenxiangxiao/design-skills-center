## 認領的首創

**顏色屬於位置，不屬於元件（attribute clash as a layout law）。** 全館第一個站，其元件的顏色不是元件自己的屬性，而是它現在站在哪一個 16×16 方塊的屬性；把同一件東西搬到隔壁方塊，它會變色，而且會連累原本住在那裡的鄰居一起換色——一個方塊只有一組三色。這條法則在全站生效（招牌、導覽、貨架、尪仔標簿），使用者可以在〈貨架〉那一頁親手操作。

## 三項核心技術

1. **自寫 2C02 PPU 圖塊渲染器**（資料與生成層）：2bpp 圖樣表、名稱表、屬性表、逐掃描線精靈評估與 OAM 輪替、掃描線分割捲動。無任何瀏覽器 API 依賴，Node 22 實測 **0.62 ms／幀**（預算 16.6 ms）。
2. **Gamepad API**（輸入與感測層）：這個流派的原生輸入裝置就是手掣。MDN 標示 Baseline Widely available（2017-03 起）。鍵盤／滑鼠／觸控路徑永遠在，功能完全相同。
3. **CSS `zoom`**（版面與樣式層）：承載「只做整數倍放大」這條硬規則。Firefox 126（2024-05）實作完成後進入 Baseline newly available；不支援時以 `@supports not (zoom: 2)` 讓 `--u` 自己等於 N 像素，不需重複任何一條規則。

## 保底

- 關掉 JavaScript：導覽、營業資訊、二十四樣貨的價目表、店史、店規、技術說明全部還在，一個字也不會少；只有畫面區不繪製。
- `prefers-reduced-motion`：環境動效凍結在第 0 幀、轉場改為直接切換、精靈不輪替改為固定丟棄並在狀態列指名是哪幾件——資訊零損失。
- 手機（≤560px）走 ×1 放大，畫面 256px 寬，任何手機都放得下；欄數、順序、內容不變。
