工法與沿革

這一頁講三件事：這門手藝從哪裡來、一面稜面牆的五條規矩、以及這座網站怎麼把「光決定顏色」這件事做成真的。

DNEŠNÍ SVĚTLO ／ 今日光向 此刻：12:00　正午・光自上方 這一頁上每一塊灰泥的明暗都是這個光向算出來的，不是選出來的。光整天在走，牆整天在變。

沿革

1911　一群從華沙、維也納與巴黎回來的年輕人在布拉格組了 Skupina výtvarných umělců（造形藝術家團體）。建築師 Pavel Janák 在團體的刊物上寫了〈稜面與斜面〉：水平與垂直是物質的靜止狀態，只有插進第三個平面——斜面——物質才會活起來。這句話後來被照著蓋成了房子。

1912　Josef Gočár 的黑聖母之家在采萊特納街落成，一樓開了 Grand Café Orient——世界上唯一一間立體派咖啡館。同年 Josef Chochol 在維謝赫拉德山下蓋了幾棟公寓與別墅，整面立面被切成稜。Vlastislav Hofman 把同一套邏輯用在家具、燈柱與陶器上。

1914　戰爭。工坊關門，模架上的模留下來。

1918–25　戰後 Janák 與 Gočár 把稜換成圓弧與紅白配色，做出所謂的圓弧立體主義（rondokubismus），也就是「國族風格」。那是另一件事，本工坊不做。

現在　全世界的立體派建築幾乎都在布拉格，數量不到五十棟。它們的立面每隔二三十年就要修一次，因為稜面比平面容易積水。修的時候得重放樣、重翻模——這就是這間工坊在做的事。

為什麼只有布拉格有

因為只有這裡的人把立體派畫裡的東西當成建造指令而不是繪畫技法。巴黎的立體派在畫布上把物體拆開；布拉格的立體派拿灰泥把牆折起來。這是唯一一次有人把一個繪畫運動翻譯成一種砌牆的方法，而且真的砌出來了。

一面稜面牆的工法

先量光，再畫圖

放樣的第一件事不是量牆，是記下這面牆一天裡什麼時候受光、光從哪個方位來。朝北的牆一整天只有低角度的散光，那面牆的稜高就得整體拉高一級，否則到下午整面糊掉。朝西的牆下午三點以後對比極強，稜高反而要壓低，不然影子會把窗洞吃掉。

樣板牆

排完模一定先在原尺寸的樣板牆上砌一次，而且至少要看兩次：一次中午，一次日落前四十分鐘。刷掉最多設計的是第二次。

稜高不是厚度

模冊上的稜高一到四，指的是這副模在光下能拉開幾階，不是它有多厚。稜高一的楔只有一個面，它永遠只有一個讀數；稜高四的斜脊切成十層以上，任何角度的光都能在它身上找到四階。所以稜高四的模貴一倍以上——它買的是「在黃昏還讀得出來」。

相鄰不得同稜高

工坊的鐵律。兩塊同稜高的模並排，中午分得出來，天一斜就併成一塊，接縫就沒了；而接縫是這面牆唯一的結構證據。這條規矩寫在拼模台的驗收單上，師傅只驗這一項。

填縫的人與砌牆的人不是同一個

砌的人會下意識把自己的縫填得漂亮，於是把該看見的縫填掉。這是規矩，不是分工。

PĚT RYSŮ

本風格的五個不可省略特徵

拿掉其中任何一項，畫面就不再是這個流派。完整的可複製規格（含 CSS/SVG 片段）在 SKILL.md。

RYS 01

斜面統治所有角度TŘETÍ ROVINA

畫面上任何一個轉折只能是 30° 或 60°，不能有第三個角度，也不能有曲線。水平與垂直只准出現在承重的地方——地板、簷口下緣、表格線。裝飾層裡一條垂直線都不准有。

RYS 02

四階平塗，沒有漸層ČTYŘI TÓNY

每一塊面只有一個顏色，色階只有四階。沒有 gradient、沒有模糊陰影、沒有柔邊。灰泥不會漸層——它是一個平面，一個平面在一個光下只有一個讀數。

RYS 03

色是算出來的，不是選出來的SVĚTLO ROZHODUJE

每一面的顏色 = 它的法線與此刻光向的內積，量化成四階。設計師不指定顏色，只指定形狀與朝向；顏色是後果。所以整站的畫面一天之內會換好幾次，而形狀一動也不動。

RYS 04

鋸齒簷口與菱形開口ZUBY A KOSOČTVERCE

收頭一律是鋸齒，不是直線也不是圓角。開口一律是菱形或六邊形，不是矩形。這兩件事是這個流派在街上最容易被認出來的兩個記號。

RYS 05

每一條稜都要描出來HRANA JE ČÁRA

兩個面交會的地方必須有一條墨線，線寬隨稜高遞增（稜愈深線愈粗）。這不是描邊裝飾——它是為了讓清晨與黃昏那兩段光讀不出色階的時候，形狀還在。

ŠESTNÁCT TÓNŮ

此刻的十六階

四種稜高 × 四個朝向 = 十六個讀數。這十六塊色不是色票，是十六個平面在你此刻的時間下的明暗。整站的每一塊灰泥都取自這張表，沒有第十七個顏色。放著不動，過一小時再看一次。

技術實作與相容性

整站不使用任何函式庫、任何外部圖片與音檔；圖像全部由頁內的稜面引擎輸出成 SVG。所有明暗來自十六個 CSS 自訂屬性，這些變數掛在 html[data-phase] 上，因此關掉 JavaScript 時畫面仍是完整的（停在正午那一階）。

mix-blend-mode: multiply
A 渲染層		 承擔全站的影子（街樹影、凹槽）。畫面上同時存在四階灰泥，任何用固定色畫的影子都會在其中一階上失真；multiply 讓同一塊影子在四階上各自正確地暗一階。查證（2026-09-05，MDN／caniuse）：Baseline Widely available，2020-01 起跨瀏覽器（Chrome 41+／Edge 79+／Firefox 32+／Safari 8+），全球約 96%。不支援時影子退為半透明實色疊層，位置與形狀不變，資訊零損失。
CSS Grid subgrid
C 版面與樣式層		 模冊與模卡用它——每張卡的圖、名稱、說明、規格四列共用外層網格的列軌，因此不同長度的說明文字不會把規格列擠歪，二十四張卡的稜面圖底邊在一條線上。這正是這門手藝的規矩：稜線要跨件連續。查證（2026-09-05，web-features explorer／MDN／caniuse）：Baseline Widely available 自 2026-03-15；Firefox 71（2019-12）、Safari 16（2022-09）、Chrome/Edge 117（2023-09）。不支援時以 @supports not (grid-template-rows:subgrid) 退回 flex 直排並把規格列推到底，四列內容全在、只是不跨卡對齊。
真實時刻驅動的光向
B 動效與時間軸層		 以 Date 取得裝置本地時刻，落在日出 06:18 與日落 19:22 之間切成八段、夜間一段，寫進 <html data-phase>；十六個色階變數隨之整批換值，每 30 秒檢查一次。沒有滑桿、沒有開關——光是外部條件，不是參數。查證：Date、setInterval、CSS 自訂屬性皆為 Baseline Widely available（2020 年前即跨瀏覽器）。無 JavaScript 時 data-phase 停在 HTML 內寫死的正午值，畫面完整。
效能 單頁最大 115 KB（含全部 inline 資源與 SVG），無外部 JS／CSS 除 Google Fonts。首屏無 JavaScript 版面工作——所有 SVG 在建置階段就算好寫進 HTML。拼模台每次重繪重建一次 600×400 的 SVG（約 15 KB、約 400 個節點），實測單次 <6 ms。求解器（「師傅代砌」）在空牆上實測 18 ms（Node 22 單執行緒，回溯法、以第一個空三角面為錨），上限 60 萬步，超過即回報砌不下去。
動效與降級 四種：街樹影橫移（環境，24 分鐘一輪）／落模預覽與模架轉面（輸入，<100 ms）／脫模顯影 steps(4)（轉場）／轉面向光（簽名）。prefers-reduced-motion: reduce 時樹影停在定點、所有 transition 歸零、脫模動畫不播——四種的資訊全部由靜態畫面承擔，零損失。
