## 為什麼是這個配對

Frutiger Aero 的產業論述是「科技是乾淨的、有機的、對人友善的」——水、空氣、草、泡泡、透明的東西。但這個流派在網路上被復刻時幾乎都被做成「加光澤」：整頁都在發亮，字沒辦法讀。

水族店比誰都清楚那條真正的規矩：**缸裡的東西好看，缸外的東西才好讀。**標價牌貼在玻璃上不是因為懶，是因為貼在水裡會晃、會歪、會被藻蓋住。所以這一站把整個風格重寫成一條材料規則：

> **濕的東西給人看，乾的東西給人讀。**

## 開場／導覽／插畫／氛圍／簽名

- **開場 `tankface-first` 缸面直開場**：首屏不是一張圖，是一個有厚度的透明體。同一屏的資訊分在三個深度上——玻璃外（乾：營業時間、電話，永不位移）、水中（濕：店名與價目，有高光、會錯開）、壓在砂上（最深：地址，偏青、低對比，因為水把紅光吃掉了）。
- **導覽 `sucker-set` 吸盤導覽**：四頁＝缸邊四個吸盤。現用的那一個**吸住了**——中間的空氣被擠光、整片貼平、顏色變深、邊緣一圈被壓出去的水；其餘三個只是靠著，中間還有一層水膜與兩顆氣泡。語意是「這一個與玻璃之間現在沒有東西」。差異對輔助科技不可見，所以現用項同時帶 `aria-current="page"`。
- **插畫 `wet-body` 濕體構成**：三個原語——濕體（本體色＋朝光高光＋背光回色）、水（只有垂直的顏色吸收與氣泡，零波紋貼圖零雜訊）、生物（只有一種筆畫，末端朝光）。
- **氛圍 `aqua-daylight` 水光**：天空到水的垂直漸層為唯一大面積底色，**允許且需要純白**（全館極少數不禁純白的站），草綠為唯一的第三色相。漸層只能垂直、模糊只能在水面以下。
- **簽名動效 `refraction-shift` 折射位移**：燈一動，水裡的東西不是變亮而是**錯開**，而且越深錯得越多；玻璃外的完全不動。位移量由 Snell 定律算出：`depth × tan(asin(sin(入射角)/1.33))`，全部寫在 CSS 裡。

## 認領的首創

**濕與乾作為全站唯一的材料軸，且它決定資訊的可讀性。**

全館第一個把每一個元素明文分成「濕的」與「乾的」，而且這個分類不是裝飾：濕的東西會隨光源位移與變亮（所以它在某些光下比較難讀），乾的東西永遠不動。站上因此立下規則——**任何必須被讀到的長文一律是乾的**，濕的那一層只放可以被移動、可以被看不清楚的東西。使用者移動指標就能當場驗證哪一層是水、哪一層是玻璃、哪一層是空氣；而導覽的現用狀態用的也是同一條規則（吸盤與玻璃之間有沒有水）。

與既有首創最需辨明：`ridgeline`／`compositie-optiek` 的 3D 場景與 `nordvarsel` 的 GLSL 極光是渲染引擎；幾何光線光學站（反射／Snell／稜鏡色散）是一台可操作的光路模擬器，光路本身就是內容；`leung-kee` 的真實時刻晝夜引擎是時間驅動的環境色溫，全畫面一起變；`chuangkou` 一類的彩光投影是真實日照時刻在版面上移動。本站沒有模擬器、沒有場景、也不跟時間有關——它是一條**貫穿整份樣式表的材料與可讀性規則**，而唯一的輸入是使用者的指標。

## 核心技術

| 層 | 技術 | 承擔 |
|---|---|---|
| C 版面與樣式 | CSS 三角函數 `atan2()` `sin()` `asin()` `tan()` `hypot()` | 高光方向與強度、Snell 折射位移、草的傾角。整站幾何零 JavaScript |
| A 渲染 | CSS `mask-composite: exclude` / `intersect` | Aqua 鈕的上弦月高光是「一個圓減去另一個圓」，不是畫一個白橢圓 |
| B 動效與時間軸 | View Transitions API（跨頁 `@view-transition` ＋ 同頁 `startViewTransition()`） | 換頁的沉下／浮上；認養單開出時的重繪 |

支援現況、查證來源、fallback 具體行為與效能實測值，見 `SKILL.md` 第十二章。

## 動效預算（四種齊備）

1. **環境** 氣泡上升（26 顆，各自的週期與相位）
2. **輸入** 指標即燈：所有濕面的高光即時重算，rAF 內一次寫入，零版面讀取
3. **轉場** View Transitions：沉下去／浮上來
4. **簽名** 折射位移

四種都有 `prefers-reduced-motion` 降級，且**降級後資訊零損失**——所有內容都是靜態 HTML，動效只承載材質。
