# 洗園所 Sé-hn̂g — 造園渲染與紅書

台南中西區一間虛構的造園渲染所。業主要改一個埕、一個天井、一段廊下，所裡不出三維透視圖，出一本**紅書**：左邊是現況，右邊掀起紙翼是提案。兩張圖同一個視點、同一批顏料，所以看到的差別就只是真的要改的那些。

## 核心功能：留白簿

三句話：

1. 一張紙上最白的地方，是你從來沒碰過的地方。
2. 四道洗（天光／綠／暖／暗），次序固定，一道比一道深；洗下去不能收回，也沒有復原。
3. 每一道洗之前先圈要留的，撕膠之後才知道你留對了沒有。

題目是一個後埕的十四個區。每一道洗之前你決定哪幾區上留白膠，按下「洗」，其餘的區各疊上一層——**深不是調出來的，是同一道洗疊了幾次**。四道洗完撕膠，出一張〈評紙〉：留白幾處、受光幾處、三道以上幾處，以及主筆的一句評語（依「天有沒有洗／白留了幾塊／有沒有洗到三道以上」判定，共七種）。想重來只有「重新裱一張紙」——那是丟掉這一張，不是復原。

一輪約 60–90 秒。屬遊戲／盤上型互動，不是模擬引擎：沒有量表、沒有參數、沒有物理。

## 首創（`_first_registry`）

1. **「最亮的值是一種只會變少的存量」作為互動範式** — 全館第一個把「畫面最亮的那一階不是一個可以塗上去的顏色，而是一個只能事先保留、每一次動作之後只會減少的存量」寫死成互動規則、且明文不提供復原的站。與 `ruixing-zhizha` 的 burn-to-deliver 最需辨明：那是**交付方式**不可逆（做完的東西被燒掉寄出，一次性），這裡是**過程**不可逆且必須事前規劃（每一步都在消耗一個從頭到尾不會回來的資源，而你在資訊最少的時候就得決定花在哪）。
2. **CSS 錨點定位（`anchor-name` / `position-anchor` / `position-area` / `position-try-fallbacks`）** — 經查 ledger `tech` 欄位，全館 261 站從未使用過，本站首次。

## 技術與相容性

- **抖動多邊形疊洗引擎**（自寫，E 層）：中點位移遞迴產生每一塊洗的形。**建置期執行，path data 寫死進 HTML，執行期零生成**——關掉 JavaScript，畫完整都在。
- **CSS 錨點定位**（C 層）：圖說釘在圖上並自動翻面。Baseline 2026（Chrome 125／Safari 26／Firefox 147）。不支援或無 JavaScript 時，圖說退成圖旁的段落文字，資訊零損失。
- **`@starting-style` + `transition-behavior: allow-discrete`**（B 層）：新加的一道洗淡進來。Baseline newly available（Firefox 129 起）。不支援時洗直接出現，判定結果一模一樣。本站刻意不讓任何資訊依賴 `display` 的離散轉場，所以 Firefox 不支援 `display:none` 起始動畫的限制在此完全無害。

效能：單頁最大 169.4 KB（含 inline 全部 CSS/JS/SVG，門檻 350 KB）；首屏 JS 執行 < 5 ms；動畫只改 `transform` 與 `clip-path`；零外部圖片、零音檔、零函式庫，外部資源僅 Google Fonts。RWD 至 ≤560px（對開改上下堆疊、導覽落成四等分一列、圖說改段落）。
