一間基隆的假面工坊。面坯上刻好的二十五塊分區只有兩種狀態：上墨、留素。
這一門的整套規矩都從一件事長出來——一八九〇年代的線塊版印不出灰，
所以畫面上的每一個點只能是墨或紙，中間什麼都沒有。

## 核心功能：落墨（constraint colouring puzzle）

規則三句話、九十秒玩得完，不是模擬器、沒有滑桿、沒有隱藏真值：

1. 點一塊區，決定它上墨還是留素。
2. 兩塊墨不能挨在一起——挨著就併成一團，中間那條線會**真的不見**。
3. 全面墨佔 22%–38%；兩眼與口一定留素，而且各自至少要貼著一塊墨。

寫成圖論語言：**上墨的區域必須是鄰接圖上的一個獨立集**，再加面積比與五官可讀性
兩條約束。25 區共有 55,447 個獨立集，其中 4,996 個合格（9.0%）；
隨機亂點的通過率只有 0.42%——規矩是真的擋人。

合格後發面號（例 `ML-40A0H-闊面`）、四級判詞（一等〈上得了戲台〉到四等〈碎了〉，
由墨塊數與最大塊的支配度決定）、可另存 187×258mm 的裁切稿 SVG、
可用 `?m=&t=` 分享還原、可直接帶進訂製單。

## 認領的首創

**以區域著色作為互動範式，且輪廓線是這個決定的副產物**
（region assignment as the interaction paradigm; the contour as an emergent by-product）

全館第一個站，使用者不畫任何一筆、不改任何形狀、不調任何參數——他只決定
每一塊區域該不該上墨；而**畫面上的線不是被畫出來的，是被留下來的**：
一條邊只有在兩側都留素時才存在，兩塊墨挨在一起，那條線就真的消失，兩塊併成一團。

與既有各站的分野：

* 與 **shidong**（圖地反轉作為介面狀態語法）的差別：那裡的反轉是**表達狀態的方式**，
  這裡的著色是**待解的組合問題**，而且它會刪掉幾何。
* 與 **xiulu**（WFC 約束傳播解出一面窗）的差別：那是引擎替使用者求解，
  這裡是使用者自己在約束下找解，引擎只裁定。
* 與 **baicaochun**（拖動裝字的包絡，重算排版幾何）、**rendong**（換平鋪群，重算格子）、
  **amkongtsiau**（一次手勢被拆成四塊專色版）的差別：本站沒有任何形狀被重算——
  所有幾何從頭到尾一個點都沒動，被重算的只有**每一條邊還在不在**。
* 與 **khoaibeng**（字盤佈局最佳化，有成本函數與最優解）的差別：本站沒有最優解，
  只有合格與不合格，而判準是「五官還讀不讀得出來」。

## 動效（四種，皆備 prefers-reduced-motion 降級且資訊零損失）

| 類型 | 名稱 | 說明 |
|---|---|---|
| ambient | 墨潮 ink-tide | 兩片各自太淡的墨雲以 61s／47s 漂移，整組通過硬砍濾鏡——畫面上永遠只有兩個值，動的是黑塊的輪廓 |
| input-driven | 落墨預覽 | hover／focus 時該區填鉻黃（80ms），會因此消失的線先轉成鉻黃示警（<100ms） |
| transition | 上版 plate-wipe | 進頁時 `clip-path` 硬邊由左而右揭開，`.52s steps(9)`；用 steps 是因為連續補間會產生柔邊 |
| signature | 線的生滅 | 邊的 `stroke-dasharray` 由 `50 0 50` → `0 100 0`，缺口從中央往外長（220ms）——不是 dashoffset 描繪 |

## 技術（三項，跨 A／C／E 三層）

1. **SVG `feComponentTransfer` + `type="discrete"` 硬砍**（A 渲染層）——承載特徵 1
   「紙上不准有灰」。MDN 標 Baseline Widely available（2015-07 起跨瀏覽器）。
2. **`stroke-dasharray` 中央開口作為狀態機**（C 版面與樣式層）——承載簽名動效與
   「線是被留下來的」這個主張。SVG 1.1，無支援缺口。
3. **平面區域鄰接圖 ＋ 獨立集列舉**（E 資料與生成層）——承載核心功能的規則與驗收；
   純 JavaScript，搭 FNV-1a → mulberry32 決定性偽亂數，同面號恆得同面。

查證來源、fallback 具體行為與效能實測值見 `SKILL.md` 第十二章。
