## 核心功能：穩定配對媒合

十二個人各有一份完整的順序表，全部公開印在帖上。使用者是媒人，唯一能決定的事情是**送帖的順序**：

- **送帖／退帖**——收下的帖只是暫且擱著，遇到更中意的隨時退回；退過的帖不再送第二次。這正是 deferred acceptance（Gale &amp; Shapley 1962）由使用者親手執行的版本。
- **跳序會咬人**——使用者可以違反規矩，叫某人越過他心裡更前面的人去問別戶。當下會成，結案時引擎會抓出「兩人互相都更中意對方」的私奔對，並逐對指出名次證據。
- **換誰先開口**——同一組順序表，改由另一方提親，本案六門親事**全部**換人；名次總和由 13／23 翻成 23／14。提親方最優定理被做成一顆按鈕。
- **截尾策略**——〈合婚之法〉可當場試算：吳秀娥只收前三位，從第六位升到第三位；只收前兩位，她自己落空還連累一個人。穩定機制對受親方不防策略（Roth 1982），這件事寫在頁面上而不是藏著。
- **指定親事**——郭家指名要黃麗珠。引擎枚舉 720 種配法證明這門親沒有一種牽法是穩的，並給出手指頭數得出來的鴿籠原理證明。館裡的正確反應是**退還委託金、拒絕這門委託**。

## 首創（全館第一次）

**配對市場設計（穩定婚配）作為互動範式。** 使用者的操作對象不是物理量、不是隱藏真值、不是素材，而是**十二個人的偏好序**；系統裁定的也不是對錯，而是「這個社會安排會不會自己垮掉」。三件事是全館沒有過的：

1. 使用者不能改變任何人的偏好、不能直接指定結果，他唯一的槓桿是**開口的順序**；
2. 同一組資料切換提親方，證明結果由制度而非媒合技巧決定（先開口的一方拿到所有穩定解裡對他們最好的一個）；
3. 系統會證明某個委託**在數學上不可能被滿足**，並要求使用者去拒絕客戶——不是拒絕一個違規動作（meixi-signalbox）、不是拒絕超出資料的結論（jieqian），而是拒絕一個「無論如何都會自己崩解」的安排。
