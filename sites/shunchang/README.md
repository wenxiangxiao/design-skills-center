台北通化街三十九巷的老修鞋鋪，一九八五年開業；二〇一九年起兼做二手球鞋鑑定。

## 這個站在做什麼

核心互動是**對抗性鑑定**：使用者先當鑑定師，再當造假者，兩邊看的是同一張十二項的特徵表。

1. **驗檯**（`index.html`）——桌上一雙來歷可疑的鞋，你手上是一支可調入射角的工作燈與十分鐘。
   十二項裡有五項只能在斜光（≤30°）下看、六項只能在正光（≥55°）下看、一項要開紫光；**燈角不對，那一項就是白看，系統會拒絕替你計時**。
   每查過一項且它過了，右側驗鞋單就以貝氏更新往下修一次假貨機率——而這個數字**永遠不會歸零**。
   判錯要賠：判真而它是假的，賠售價；判假而它是真的，賣家客訴。看不出來可以退件，退件收半價、不扣信譽。
2. **造假台**——換你當做假的人。這雙打算賣六千八，成本上限兩千四，十二項總造假成本是五千零二十五，所以你**必須放棄一半**。
   送去給陳師傅驗，看你在第幾分鐘露餡；即使撐過去，系統也會告訴你：你不是做對了，你只是賭對了他會先看哪幾項。
3. **六代軍備競賽**——師傅抓到人會講出去，做假的人也在看。逐代模擬下來，鑑別點會照**價錢由低到高**一項一項死掉；死掉的不是被破解，是被買走了。
   結論由模擬即時算出：十二項裡還有鑑別力的從四項掉到一項，而「必看三招」永遠是最先死的那三招。

`fa.html` 把全部規則、成本表、耗時表、貝氏算式與五條誠實聲明寫成靜態頁，**關掉 JavaScript 也讀得完**。

## 首創（全館第一）

**不對稱預算的攻防同構賽局（adversarial co-design）。**

全館第一個讓使用者**先後扮演造假方與鑑定方、面對同一張特徵表**的站：兩邊的資源不同構——做假的人受**錢**的限制（十二項全部做對要 NT$5,025，預算只有 NT$2,400），驗鞋的人受**時間**的限制（十二項全部看完要 37 分鐘，現場只有 10 分鐘）；於是同一張表正著用是抓偽、反著用是設計規避。系統以六代重複對局演示**鑑別力的耗損**：一個又快又準的鑑別點，公開講出來的那天就開始倒數，而它死掉的順序完全照價錢排。

與既有館藏的差別：

- 與 `sporekey` 二分檢索定名的差別——那是**分類**，對象沒有意圖，性狀是自然給的；本站的對象是**被設計出來要騙過你的**，而且使用者可以親手設計它。
- 與 `muli-arbor` 逆問題的差別——那是連續場的推測、誤差可算；本站是離散的**證偽鏈**，且系統永遠不輸出「這是真的」，只輸出「在哪一項上它撐不住」。
- 與 `yinweng` 毀損式抽樣的差別——那裡量測是為了估計一個數，對象無意圖；本站的核心是**對手**，破壞性檢查只是十二項裡的一項。
- 與 `beitun-bell` 即時對抗賽局的差別——那是同場競價、有時限有輸贏；本站的對抗是**離線且不對稱的**：造假者先出手、不在場，鑑定者只能面對他留下的物證。
