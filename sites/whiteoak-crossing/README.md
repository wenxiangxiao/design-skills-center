一支四十一個人的義勇消防隊，一年三分之一的預算來自三月那場泥濘拍賣會，
而拍賣會賣的是被面會縫了一整年的十二床被。
整個網站就是一床被：資訊縫在布上，導覽是一條壓線，而選取一塊布的方式叫做「疏縫」。

## 核心功能：認布（同匹布認親）

規則三句話、九十秒玩得完：

1. 每一張布樣板上，有一匹布被裁成了五塊。
2. 點出你認為出自同一匹的五塊。
3. 認滿五塊，把板子翻過來看背面的布標。

同一匹布 ＝ 同染料 ＋ 同織法 ＋ 同紗數。紗向是裁的時候決定的，磨損是穿的時候決定的，都不算。
**而顏色是陷阱**——每張板上都有四塊「同一缸染出來、但不同匹」的誘餌，
所以顏色只能把二十五塊排到剩九塊，最後那一步一定要去數紗。

在一個以「純色」為本體的流派裡，顏色恰好是唯一不能用來判斷的線索。
這是本站對「func 的判準是有沒有讓人更想要這個風格」的直接回應：
玩這個功能的過程，就是被迫把臉貼近去看這個流派的布。

十二張板皆為決定性生成（同一號永遠同一板），可用 `?lot=7` 分享與還原；
認出來的匹會記在 `localStorage`，回到拍品目錄時那一床被的卡片上會出現已認出的布名。

## 首創

**材質同源判定作為互動範式**（provenance-by-texture matching）。
全館第一個把「這兩塊東西是不是同一批材料做的」當成核心互動的站：
被判讀的不是形狀、數值、規則或色度，而是同一塊材料被裁開、轉向、
縫進不同位置之後還留著的物理指紋（浮長節奏、紗密度）。
而且「同匹」在引擎層是真實成立的事實而非標記——那五塊布的織紋確實由同一組參數畫出來。

與 zhencai「光譜配色試煉」的差別：那判的是兩個色在特定光源下是否同色（答案由光譜與光源決定），
本站判的是兩塊布是否來自同一匹（答案由織法與紗數決定），而且**色相被刻意做成不可靠線索**。
與 sporekey 二分檢索、muli-arbor 逆問題、xiulu WFC 約束傳播皆不同。

## 四種動效

| 類型 | 內容 |
|---|---|
| ambient 環境 | **針趾行進**：內窄框那一圈壓線的針一針一針往前走（`steps(60)`，30 秒一輪，永不停） |
| input 輸入 | **布鏡**：游標／Tab 移到哪一塊，側欄就把那塊布的織紋放大 2.6 倍（<100ms）。布鏡只放大，不給答案 |
| transition 轉場 | **上布**：換板時二十五塊布依序被鋪上去（`@starting-style`，每塊延遲 34ms） |
| signature 簽名 | **拆線掀被**：一條地色的縫沿對角線長出來（線被一針一針抽走），被面沿那條縫裂成兩片向外翻折，露出裡布與手縫布標 |

四種皆有 `prefers-reduced-motion` 降級，降級後資訊零損失。

## 技術

- **`subgrid`**（Baseline Widely available 2026-03）：整站的主縫線；拍品卡片以列方向 subgrid 巢狀兩層，讓十二張卡的橫縫跨欄對齊。
- **`pathLength` ＋ `stroke-dasharray`**（SVG 1.1，全瀏覽器）：讓「每吋幾針」「每吋幾紗」成為宣告值而非量測值。四條共用織紋路徑（9.0 KB）撐起全站所有布面。
- **`@starting-style` ＋ `transition-behavior:allow-discrete`**（Baseline newly available 2024-08）：進場與面板轉場零 JS 計時器。

單頁最大 64.1 KB（門檻 350 KB）；最重一頁的圖像生成 1.99 ms（門檻 100 ms）。
零外部圖片、零音檔、零 JS 函式庫，外部資源只有 Google Fonts 兩支字體。
