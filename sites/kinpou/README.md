**舊衫回收分類場兼零碼布批發（論斤賣）× 拼布 Quilt（Gee's Bend 即興拼布）**

臺南西港糖廠舊倉庫後身的一間舊衫分類場。收舊衣、分等、論斤賣布給做抹布的、做包的、縫被的。每月第一個週日「翻布日」把三年以上的架布全倒出來，一斤五塊。門口那面被子是分類頭手蔡阿蕊用歷年賣不掉的布縫的——一塊布在架上超過三年，就縫上去。

## 核心功能：補布市

規矩三句話，九十秒玩得完：

1. 你手上六塊布，巷子裡三個熟人，每個有自己的規矩。
2. 一次提一組交換（你出幾塊、換他哪幾塊），他照規矩當場答應或回絕。
3. **四手**以內湊到縫得成一床單人被面（五尺寬八尺長），就縫。

縫得成的判準：面積 ≥ 40 平方尺、色 ≥ 4 種、質地 ≥ 2 種、最大一塊 ≤ 總面積四成。

三條規矩是三條可驗算的述詞：

- **阿桂**：出的必須全部同一質地，且塊數＝拿走的兩倍。
- **水源伯**：出的不得含破角的，且出的面積 ≥ 拿走的面積＋2。
- **阿雪**：塊數相同，且出的顏色與拿走的顏色不得有交集。

實測（Node 22，同一套規矩與發牌）：隨機 300 堆布，開局即成立 0 堆；四手內有解 207 堆（69.0%，最短一手 13／兩手 175／三手 19）；四千次「亂換」四輪後成功率 0.3%。**三堆裡約一堆本來就湊不齊——翻布日本來就是這樣。**湊不齊就再翻一次，不扣分、不排名、不給星等。

## 認領的首創

**配色權既不在設計者也不在使用者手上（colour authored by neither designer nor user）**

全館第一個站，其畫面的顏色由兩個沒有人在操作的來源決定：

1. **版面的顏色由內容的長度決定。** 頁面上每一塊區域都沒有 `background-color`；它的布是照它自己的**高度**一塊一塊接出來的（Lazy Gal：一條帶子的長度是手上那塊布決定的，不夠就接、接處換色）。改變視窗寬度、放大字級、篩選卡片、在市場換一手——該區塊當場多接一塊布並換一次色。設計者只決定調色盤裡有哪幾塊布，不決定它們落在哪裡。
2. **成品的顏色由交換結果決定。** 核心功能沒有任何一個色票可選：你要的顏色來自別人手上有什麼、以及他肯不肯換。這正是這個流派之所以長成這樣的原因。

與既有各站的差別：`yongzi-foundry`（識別可被訪客接管）改的是字形骨架、`baicaochun`（包絡熔字）改的是排版容器、`zhencai`（換燈重演色）與 `shunchang`（換光角重新打光）改的是顏色**但由使用者操作的燈與角度決定且可逆**、`rendong`（無邊界產出物）的顏色是使用者選的三到五種苗。本站的顏色沒有任何人在選：一半來自 DOM 的高度，一半來自一場交易的結果，而且兩者都不可回頭調。

## 技術（三項，見 `kin.html#tech` 與 `SKILL.md` 第十二章）

1. **CSS Grid `subgrid`**（版面層）— Housetop 三圈布咬同一組不等寬格線；目錄卡片橫列切齊。Baseline newly available 2023-09-15。`@supports not` 備援。
2. **`mix-blend-mode: multiply / screen`**（渲染層）— 燈芯絨棱紋順逆對調。Baseline widely available 2020-01。不支援時退為 `normal`，版面不變。
3. **純 JavaScript 規則引擎 + FNV-1a → mulberry32 決定性偽亂數**（資料與生成層）— 補布市的三條述詞、所有插圖、`?q=` 分享碼還原。無 API 依賴。

四種動效：ambient 曬被（84s 硬邊日光橫掃）／input 順毛逆毛（90ms 棱紋對調）／transition 攤被（`clip-path` 由中線向兩側展開 560ms）／signature 不夠長就再接一塊（`steps(7)` 一針一針縫下來）。四種皆有 `prefers-reduced-motion` 降級且資訊零損失。
